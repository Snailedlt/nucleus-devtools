Make a handler with AI

AI can write a handler. Check it before you trust it.

ChatGPT, Claude, Gemini, Copilot and the rest know a little about Nucleus Co-op, and fill the gaps with guesses that look right. Nucleus quietly ignores an option it doesn't know, and refuses to load newer JavaScript, so a handler can look fine and do nothing. The fix is simple: let the AI write, and let the tools check.

  • 💬In a chatChatGPT, Claude, Gemini, Copilot Chat, a local model: no setup.
  • ✦With an agentClaude Code, Copilot agent mode, Cursor: it checks its own work.
  • In the workbenchFix with AI and Explain this line, next to the checks.

What AI gets wrong

The same few mistakes, over and over. Every one of them is caught by the checks, which is why the loop below works.

  • Newer JavaScript. Nucleus runs handlers with an old engine (Jint 2.11): arrow functions, `template ${strings}`, classes and .includes() don't load or don't run. es5-only, missing-builtin
  • Invented options. Game.ForceFinishOnPlay, Game.IgnoreWindowBordercheck, ProtoController5: they sound right, Nucleus ignores them, and the handler "works" without doing what it says. unknown-member
  • Context in the wrong place. Context only exists inside Game.Play and the other callbacks; at the top of the file it stops the handler from loading. callback-only-global
  • Wrong types. Game.KillMutex = "name" needs a list, ["name"], or the whole handler fails; Game.DPIHandling = true quietly picks a mode you didn't mean. type-mismatch
  • Lines the Hub can't read. Game.GameName and Game.ExecutableName on their own lines, in double quotes, or installing from the Hub breaks. hub-install-parse

In a chat: write, check, fix, repeat

Any chat AI works, free or paid. It can't run anything, so you carry the code between it and the workbench.

  1. Start with the rules. Paste the prompt below first, then describe your game. The more facts you give (engine, the .exe's name, how it does multiplayer, where it keeps its settings), the less it guesses. PCGamingWiki has most of them.
  2. Paste its handler into the workbench (open it and paste over the template) and look at Check. Fix problems applies the safe fixes in one go.
  3. Send back what's left. Copy each problem's message to the AI and ask it to fix only those. Don't let it rewrite the whole handler: it tends to bring old mistakes back.
  4. Try it shows what each player gets: their window, launch arguments and the files Game.Play changes. If something is wrong there, tell the AI what you see.
  5. Test in Nucleus. Turn on its debug log (Settings), play with two players, and give the AI debug-log.txt from the Nucleus folder along with what happened.

The starter prompt

Copy it into a new chat, then add your game underneath.

You are helping me write a Nucleus Co-op handler: the JavaScript file Nucleus Co-op (SplitScreen.Me) uses to run several copies of a PC game split-screen, one per player. Follow these rules exactly:

1. ES5 JavaScript only. Nucleus runs handlers with Jint 2.11: no arrow functions, template strings, classes, let/const (use var), destructuring, spread, default parameters, for...of, ?. or ??. No .includes(), .startsWith(), .find(), Object.assign, Map or Set: use indexOf, loops and plain objects.
2. Only use options that really exist. Nucleus silently ignores a misspelled or invented option. If you are not sure an option exists, say so and ask me to check it, instead of guessing.
3. Context, Player and PlayerList only exist inside callbacks such as Game.Play. Top-level code only sets Game.* options.
4. Required: Game.GUID (letters, digits and spaces only), Game.GameName, Game.ExecutableName (the .exe's file name, never a path).
5. Write Game.GameName = "..."; and Game.ExecutableName = "..."; each on its own line, not indented, in double quotes, with no other " on the line.
6. List options take arrays: Game.KillMutex = ["name"];. Booleans are true/false, numbers are numbers. Pass every argument to a method, even ones that look optional.
7. Game.Play runs once per player: use Context.PlayerID (0-based), Context.Width and Context.Height there, and set Context.StartArguments for the command line.
8. Don't add Hub.* lines; the Hub writes them.

When you change the handler, change only what I ask, give me the whole file, and say what each change is for. Ask me for facts about the game you don't know (engine, .exe name, how multiplayer works, where settings and saves are) rather than inventing them.

The full list of options, with their types and docs, is in Docs. If your AI can open links, give it the API reference (large) and the handler guide written for AI.

With an agent: it checks its own work

Agents that can run tools (Claude Code, GitHub Copilot in agent mode, Cursor, Claude Desktop) can use the same checks as the workbench, so they fix their own mistakes before you see them. Set it up once (how, for each agent), then ask for what you want:

Make a Nucleus Co-op handler for <game>. It's on <engine>, the exe is <Game.exe>, and multiplayer is <LAN / Steam / online only>. Check it and Try it with 2 and 4 players before you give it to me.
  • It looks things up instead of guessing: every option it uses, and how existing Hub handlers for the same game or engine solved it.
  • It checks and runs the handler per player, the way Nucleus would, and fixes what fails.
  • It hands you a test plan: what to try in Nucleus and what to send back. It can't run the game for you.
  • It signs its work: a few lines at the top of the handler say an AI wrote it and what was checked, so people who help on Discord know where to start.

In the workbench

  • Fix with AI sends the handler and its problems to an AI and shows what it would change, before and after, to apply or discard. Use your own key (Claude, OpenAI, OpenRouter, Gemini) or a free local model (Ollama, LM Studio): Settings › AI. The checks run again on what comes back.
  • Explain this line (Ctrl+Alt+E) says in plain words what a line does, from the docs; no AI needed. Handy for reading what an AI wrote.

Before you share it

A handler that passes every check can still not work: the checks know Nucleus, not your game. Test it with two players in Nucleus first, and say it was made with AI when you post it on the Hub or ask for help, so others know to look at the details.
